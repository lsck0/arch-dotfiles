# Arch Linux-LSCK0

The install iso: plain Arch (archiso's `releng` profile) plus the dotfiles installer. It boots to an autologin on tty1
that reads an optional answer file, gets the machine online (a cable is automatic, Wi-Fi gets a picker), then runs this
repo's `bootstrap.sh`, which clones the newest signed master and starts `dot internal bootstrap`. Everything after
that, the reboot and the unattended stages, is the same as from the official iso. The iso is online-only: the installer
does not start the bootstrap until https://mirror.lsck0.dev and https://github.com both answer.

Download: https://mirror.lsck0.dev/iso/ (`archlinux-lsck0-latest-x86_64.iso`, or a dated one).

## What is in it

- `packages.x86_64`: added to releng's list (nushell, git, dialog, and the YubiKey tools the bootstrap's secrets
  step uses: pcsclite, ccid, yubikey-manager, age, age-plugin-yubikey, git-crypt, libfido2). `pcscd.socket` is
  enabled by releng already. Networking is releng's own iwd plus systemd-networkd: nothing extra, and iwd's
  `iwctl` drives the picker.
- `profiledef.sh`: releng's, with `iso_name`, `iso_label` (`ARCH_LSCK0_<YYYYMM>`) and a 1 GiB copy-on-write
  overlay (`cow_spacesize=1G`). Boot menus and everything shown after boot stay releng's.
- `airootfs/`: copied over releng's; a `*.append` file is appended to releng's file of that name.
  `usr/local/bin/lsck0-install` is the installer, `root/.zlogin.append` starts it on tty1.
- Generated by the build: `/etc/pacman.conf` gets the `[lsck0]` section of `configs/base/pacman/pacman.conf`
  (last, so core and extra win for pacstrap), its key `configs/base/pacman/archrepo.asc` lands in the iso's keyring
  (populated at boot), and a shallow checkout of the commit being built, verified against the signing key the way
  `bootstrap.sh` verifies its clone, sits in `/usr/share/lsck0/arch-dotfiles` as the launcher.

## Answer file

`lsck0.nuon` (`lsck0.example.nuon` lists every key) answers the bootstrap's questions; a missing key is asked, an
invalid file stops with one line before anything is written. The installer looks, in order, on:

1. the boot medium, then a partition labelled `LSCK0` (a FAT32 partition added to the stick's free space after
   writing the iso), then every other FAT, exFAT, NTFS, UDF or ISO 9660 medium: `lsck0.nuon` at its root or next to
   an `archlinux-lsck0*.iso` (a Ventoy stick);
2. `lsck0.answers=<url or path>` on the kernel command line, fetched once online;
3. `lsck0.<key>=<value>` on the kernel command line, one key each (`lsck0.wifi.ssid`, `lsck0.wifi.psk` for one
   network), overriding the file.

Keys map onto the bootstrap's `BOOTSTRAP_*` variables (`scripts/lib/bootstrap.nu`'s header): `profile`, `platform`,
`username`, `hostname`, `disk`, `keymap`, `timezone`, `locale`, `groups`, `ssh_key`, `encrypt`, `server`,
`home_network`, `secure_boot`, `password`, `user_password`, `root_password`; `unattended: true` is
`BOOTSTRAP_ASSUME_YES` (no summary, no erase confirmation). `wifi` is a list of `{ssid, psk, hidden}` tried in order
before the picker. `source` (`{bundle, lfs}`) installs an unpublished tree, unverified: the vm test uses it.

## Build

```bash
dot internal iso [--out DIR] [--work DIR] [--mirror URL] [--sign FPR] [--keep N]
```

- Needs `archiso` (declared by `qemu/libvirt`) and root for `mkarchiso` (it calls `sudo` unless it is root),
  about 10 GB free in the work dir and 10 minutes.
- Work dir: `--work`, else `$DOT_ISO_WORK`, else `~/.cache/dotfiles-iso`; emptied after a successful build.
  Output: `--out`, else `<work>/out`.
- Network: only the Arch mirrors in the host's `/etc/pacman.d/mirrorlist`, or `--mirror` (a pacman `Server` line's
  URL, `$repo` and `$arch` included, e.g. `http://10.100.0.104:8090/archlinux/$repo/os/$arch`). No GitHub, no AUR,
  no [lsck0] packages: the checkout comes from the repo it runs in, which must have its HEAD signed by the key in
  `bootstrap.sh`, else the build stops.
- Output, all in the output dir: `archlinux-lsck0-<YYYY.MM.DD>-x86_64.iso` (the build date), its `.sha256`, the
  symlink `archlinux-lsck0-latest-x86_64.iso` and `archlinux-lsck0-latest-x86_64.iso.sha256` (naming the latest
  file, so `sha256sum -c` works on a download of either name). `--sign FPR` adds `.sig` (and a latest `.sig`
  symlink) with that key from the caller's gpg keyring. `--keep N` (default 3) deletes older dated isos and their
  `.sha256`/`.sig` in `--out`. Every path is printed, any failure exits nonzero, nothing is asked.

## Homelab handoff

The homelab builds it on vm-112 after the nightly [lsck0] package build, signs it in its own publish step and serves
it at https://mirror.lsck0.dev/iso/:

- build, as root in a checkout of signed master (no submodules or lfs needed):
  `nu --no-config-file scripts/dot.nu internal iso --work <dir> --out <dir> --mirror <lan mirror> --keep 1000`;
  retention is the publish step's, not `--keep`.
- publish: the dated iso, `.sha256`, `.sig` (repo key `88042EFBF5F141C2ACF4697ADD84D7C4053DD354`), the
  `archlinux-lsck0-latest-x86_64.iso` names pointing at the newest, and `lsck0-signing.asc`.
- retention: the newest, the first of each month and the first of each week (Monday), like the package snapshots.
- a failed build keeps the previous files.

Links: [latest](https://mirror.lsck0.dev/iso/archlinux-lsck0-latest-x86_64.iso),
[sha256](https://mirror.lsck0.dev/iso/archlinux-lsck0-latest-x86_64.iso.sha256),
[sig](https://mirror.lsck0.dev/iso/archlinux-lsck0-latest-x86_64.iso.sig),
[key](https://mirror.lsck0.dev/iso/lsck0-signing.asc), [all builds](https://mirror.lsck0.dev/iso/).

## Verify a download

The installer does not check the iso itself. The signing key is the [lsck0] repo key, the same one pacman trusts on
every installed machine; this repo's `configs/base/pacman/archrepo.asc` is the trust anchor, the download
https://mirror.lsck0.dev/iso/lsck0-signing.asc a copy of it. Fingerprint `88042EFBF5F141C2ACF4697ADD84D7C4053DD354`.

```bash
gpg --import lsck0-signing.asc
gpg --verify archlinux-lsck0-<date>-x86_64.iso.sig archlinux-lsck0-<date>-x86_64.iso
sha256sum -c archlinux-lsck0-<date>-x86_64.iso.sha256
```
