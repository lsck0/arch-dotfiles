# desktop/hyprland

Extends the root `AGENTS.md` and the `configs/desktop/AGENTS.md`. The Hyprland compositor config, written in Lua.

## Layout

- `hyprland.lua`: the entry point. Requires each `hyprland_*` module in order (`hyprland_powersave` last, it overrides
  the rest), dropping `package.loaded` first so a config reload re-runs them.
- `hyprland_*.lua`: the sections: `autostart`, `cursor`, `input`, `keybindings`, `layout`, `misc`, `monitors`,
  `plugins`, `powersave`, `windowrules`, `windows`.
- `platform.lua`: generated by `mod.nu` into `~/.config/hypr` from the module's options (`dot set
  desktop/hyprland`): form factor, monitors, main monitor, workspace layout, xwayland scale, app homes, keyboard and
  pointer, the keyboard backlight. The display options are detected from `hyprctl` when no platform value is set; no
  detection in the lua.
- `hl.meta.lua`: the type stub for the global `hl` api (LSP only).
- `wal_colors.lua`: the wallust palette, dropped and re-required on reload.
- Helper scripts: `boomer.nu`, `screenshot-region.nu`, `screen-dim.nu`, `lockscreen-stats.nu`,
  `quickshell-lock-launch.nu`, `plugins.nu` (hyprpm), `window-close.nu` (`SUPER+Q`: closes the active window, kills
  a gamescope one that ignores the request). Config in `hypridle.conf` (idle timings rendered from options),
  `hyprlock.conf`, `xdph.conf` (xdg-desktop-portal-hyprland: restore tokens by default, the share picker); `shaders/`.
- `mod.nu` copies all of it into `~/.config/hypr`: an edit lands with `dot apply desktop/hyprland`, whose reload step
  puts the runtime monitor layout and shader back.

## The hl API

- Config is Lua `hl.*`: `hl.config`, `hl.bind`, `hl.monitor`, `hl.window_rule`, `hl.workspace_rule`, `hl.layer_rule`,
  `hl.env`, `hl.animation`, `hl.curve`, `hl.define_submap`, `hl.on`, `hl.exec_cmd`. Dispatchers under `hl.dsp`.
- Dispatch is Lua too (root gotcha): `hyprctl dispatch "hl.dsp.exec_cmd('cmd')"`,
  `hyprctl dispatch "hl.dsp.focus({ workspace = 3 })"`. The old `hyprctl dispatch exec cmd` fails.

## Conventions

- Per-machine behavior comes from `platform.lua`, never a hostname check: a new setting is an option in `mod.nu`,
  valued per machine in `platforms/<host>.options.nuon` (`dot set --machine`). See the `l-dotfiles-platform-facts` skill.
- XWayland scaling is `force_zero_scaling`; X11 apps scale via `GDK_SCALE` (gtk; no `Xft.dpi`, gtk would double its fonts) from the
  `xwayland_scale` option; other modules read it as `$cfg.deps."desktop/hyprland".xwayland_scale`.
